## Memory, Reflection, And Skill Induction

| Source | Representation / artifact | Experience source and induction | Applicability model | Transfer setting | Metrics reported | Negative-transfer treatment | Main limitation relative to this paper |
|---|---|---|---|---|---|---|---|
| Reflexion (Shinn et al., 2023) | Episodic verbal reflections in a memory buffer | Feedback from previous attempts is converted into natural-language self-reflection | Retrieved recent reflections; no explicit task-family trigger schema | Repeated attempts and sequential decision tasks | Success, pass@k, task reward | No explicit cross-task negative-transfer outcome | Reflection is unstructured relative to trigger-procedure-failure-mode memory |
| ExpeL (Zhao et al., 2024) | Natural-language insights plus successful trajectory recall | Cross-task trajectories are distilled into general insights; insights can be reinforced or down-voted | Similarity retrieval and learned insight relevance | Training tasks to unseen related tasks | Success rate and task reward | Misleading insights can be down-voted, but harm is not reported as a per-task transfer label | Does not isolate a fixed low-shot procedural artifact or debugging process costs |
| AutoGuide (Fu et al., 2024) | Conditional, state-aware natural-language guidelines | Offline interaction trajectories are summarized into guidelines and selected by state | Explicit state/context matching | Held-out interactive-agent tasks | Success and task completion | Selection is intended to avoid irrelevant guidance; no explicit negative-transfer metric | Guidelines are not evaluated as an ordered debugging procedure with failure modes |
| AutoManual (Chen et al., 2024) | Incrementally maintained instruction manual of rules | A builder agent interacts with tasks and adds, revises, merges, and deletes rules | Rule descriptions and state-grounded retrieval within the manual | Seen and unseen ALFWorld and WebArena tasks | Success, learning curves, rule dynamics | Discusses path dependence and distribution shift, but not per-task memory-caused negative transfer | Manual construction uses many building tasks and online updates rather than a fixed few-trajectory artifact |
| Agent-Pro (Zhang et al., 2024) | Evolvable policy with beliefs and interaction history | Failures are reflected on and translated into policy updates | Policy-level state/action guidance | Held-out interactive environments | Success and interaction performance | No explicit negative-transfer accounting | Policy optimization is broader and more online than low-shot artifact induction |
| ICE (Qian et al., 2024) | Consolidated insights from success/failure trajectories | Investigate, consolidate, then retrieve and exploit cross-task experience | Retrieval over consolidated insights | Inter-task transfer in tool-use and reasoning tasks | Success and API-call efficiency | No explicit negative-transfer label | Preprint; no real software-debugging transfer evaluation |
| Voyager (Wang et al., 2024) | Executable code skill library with descriptions | Automatic curriculum produces trajectories; successful code is stored and refined | Embedding retrieval over skill descriptions | Lifelong Minecraft exploration and new tasks | Exploration progress, task completion, skill acquisition | Failed execution triggers refinement; no transfer-harm metric | Executable embodied skills, not natural-language debugging procedures |
| LearnAct (Zhao et al., 2024) | Learned executable actions/functions | Action creation, execution, reflection, and revision from task experience | Action descriptions and environment state | New interactive tasks in the same benchmark domains | Success rate and action-learning performance | Failure is used for action revision; no explicit negative-transfer outcome | Learns callable actions rather than a fixed natural-language memory artifact |
| Agent Workflow Memory (Wang et al., 2025) | Reusable natural-language workflows induced from trajectories | Offline or online workflow induction and retrieval | Workflow retrieval conditioned on new tasks | WebArena, Mind2Web, and GAIA | Success, task progress, intermediate process | Appendix analyzes mixed-memory incompatibility, but not per-instance negative transfer | Closest workflow analogue, but not low-shot debugging or controlled structure/length ablation |
| SkillWeaver (Zheng et al., 2025) | Executable website-specific APIs | Website exploration, practice, and distillation produce reusable APIs | Website-specific skill selection | New tasks on explored websites and real-world sites | Success and skill-transfer results | Skill failures drive further practice; no explicit memory-induced negative-transfer outcome | Preprint; skill discovery is high-budget and executable rather than natural-language procedural transfer |
| Memp (Fang et al., 2026) | Fine-grained instructions and higher-level script-like abstractions | Past trajectories populate a repository that is built, retrieved, updated, corrected, and deprecated | Retrieval from an evolving procedural-memory repository | Analogous tasks in TravelPlanner and ALFWorld | Success, efficiency, and memory-strategy ablations | Update and deprecation address stale memory; no explicit per-task transfer attribution | Not a software-debugging study and does not include length/structure controls |
| ReasoningBank (Ouyang et al., 2026) | Reusable reasoning strategies distilled from successes and failures | Self-judgment and memory synthesis; retrieval is learned with memory-aware RL | Similarity or learned retrieval of reasoning memories | Multiple agent benchmarks, including SWE-bench Verified | Success, steps, tokens, retrieval ablations | Shows that excessive or noisy memory can reduce success, but does not label individual failures as negative transfer | Strongest efficiency comparator; memory is strategy-oriented and evaluation is not low-shot fixed-artifact induction |
| Skill-Pro (Mi et al., 2026) | Executable skills with activation, execution, and termination conditions | Non-parametric PPO uses semantic gradients, verification, and score-based maintenance | Explicit activation and termination conditions | In-domain, cross-task, and cross-agent transfer | Success, reuse, memory compression, and component ablations | Verification and maintenance reduce capability degradation; no explicit per-task negative-transfer outcome | Closely matches scoped skills, but not real debugging or natural-language structure controls |
| LEGOMem (Han et al., 2026) | Modular procedural-memory units allocated to orchestrator and task agents | Past trajectories are decomposed and assigned across a multi-agent system | Retrieval and placement vary by agent role | OfficeBench workflow automation | Success and memory-placement ablations | Studies placement and retrieval design; no explicit per-task transfer label | Multi-agent workflow automation rather than low-shot debugging |

## Coding Agents And Software-Defect Benchmarks

| Source | Role in this review | Task unit | Evaluation emphasis | Memory/transfer contribution | Limitation relative to this paper |
|---|---|---|---|---|---|
| SWE-bench (Jimenez et al., 2024) | Real-repository issue-resolution benchmark | GitHub issue plus repository snapshot and tests | Resolved issues under repository-level tests | Establishes realistic held-out software repair tasks | Does not define trajectory-induced memory or negative-transfer evaluation |
| SWE-agent (Yang et al., 2024) | Language-agent interface for repository repair | SWE-bench issue resolution through an agent-computer interface | Resolve rate and agent-interface design | Shows that action/interface design materially affects repair performance | Does not study learning procedural memory from prior trajectories |
| PyBugHive (Antal et al., 2024) | Reproducible Python bug database used by this project | Manually validated real Python bug and fix | Reproduction, failing/passing tests, bug metadata | Supports controlled within-project and within-family bug selection | Benchmark paper does not evaluate agent memory or process transfer |
| BugsInPy (Widyasari et al., 2020) | Foundational reproducible Python bug benchmark | Real Python bug with setup and tests | Controlled debugging and repair studies | Establishes a reproducible Python defect corpus | No agent-memory protocol; older and smaller than PyBugHive |

## Evidence Convergence

| Theme | Evidence in the verified corpus | Assessment |
|---|---|---|
| Verbal reflection can improve later attempts | Reflexion, Agent-Pro | Established, but usually evaluated through final task reward |
| Cross-task trajectories can be compressed into reusable natural-language guidance | ExpeL, AutoGuide, AutoManual, ICE, AWM | Established across interactive-agent domains |
| Reusable executable or modular skills support transfer | Voyager, LearnAct, SkillWeaver, Skill-Pro, LEGOMem | Established, especially in embodied, web, and workflow settings |
| Procedural memory is now an explicit research object | Memp, Skill-Pro, LEGOMem | Established by 2026; a broad novelty claim is not defensible |
| Process efficiency is measured in memory work | ICE, AWM, Memp, ReasoningBank | Established through steps, calls, tokens, or task efficiency |
| Agent memory can become noisy or harmful | AutoManual, AWM, Memp, ReasoningBank, LEGOMem | Recognized, but usually handled through retrieval/update ablations rather than explicit per-task negative-transfer attribution |
| Real software-repair benchmarks exist | SWE-bench, SWE-agent, PyBugHive, BugsInPy | Established |
| All target dimensions are jointly evaluated | No source in this corpus | Supported research gap, subject to the corpus limitation |
